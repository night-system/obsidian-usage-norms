# 用语规范（Obsidian 插件）

写作时在**左侧边栏**给正文出「改字」建议：只标要改的那几个字，点 ✓ 只替换那一段，点 × 就消失。
判断标准由你自己的**提示词模板**决定 —— 模板就是你仓库里某个文件夹中的 Markdown 文件，**文件名即模板名**。

> 从 [世界游戏](https://github.com/night-system) 项目里的「辅助书写」移植：
> 五字段输出契约、本地硬校验、按句增量、扫描记账，这套逻辑原样搬过来；
> 交互从「右侧栏」改成 Obsidian 的**左侧边栏**，设置从 App 内的弹窗改成 **Obsidian 设置页**。

---

## 安装（BRAT）

1. 安装并启用 [BRAT](https://github.com/TfTHacker/obsidian42-brat)。
2. 命令面板 → `BRAT: Add a beta plugin for testing`。
3. 填仓库地址：

   ```
   night-system/obsidian-usage-norms
   ```

4. 启用插件「用语规范」。以后 `BRAT: Check for updates` 就能更新。

手动安装也可以：把 Release 里的 `main.js`、`manifest.json`、`styles.css` 放进
`<你的库>/.obsidian/plugins/obsidian-usage-norms/`，再在「第三方插件」里启用。

## 第一次使用（两步）

1. **设置 → 第三方插件 → 用语规范**
   - **提示词模板文件夹**：选一个只放提示词文件的文件夹（不要选笔记根目录）。该文件夹里每个 `.md` / `.txt`
     文件就是一个模板：文件名是模板名，文件内容是提示词正文。点一行设为默认；右上角 `+` 可以直接新建。
   - **DeepSeek 密钥**：填 `sk-…`，点「测试」确认能连上。
   - 思考强度（低 / 中 / 高 → 一次最多 3 / 5 / 8 条）、是否显示 `reason` 也在这里。
2. 点左侧栏的 ✨ 图标（或命令 `用语规范：打开 / 聚焦左侧面板`），面板就挂在左边。

## 用的时候是什么样

面板里**只有一行行建议，别的什么都没有**（没有顶栏、没有按钮、没有空态文案）：

```
×  然后观察匹配机制是否正常工作          ✓
   第一类 - 第5条
```

- 打开面板：命令 `用语规范：打开 / 聚焦左侧面板`（或左栏的 ✨ 图标）；
- 全文扫描：命令 `用语规范：全文扫描当前笔记`（面板上没有扫描按钮了）；
- 换模板 / 换强度 / 改密钥：全在**设置页**；
- **开栏不整篇扫**：只有「你这次改动真正碰到的那一句」会被送检；整篇用上面的命令；
- 句号 / 换行落下、且这一句刚被改过 → 立刻送整句；光标停在句子里（含已有的老句子）停手约 0.9 秒 → 先出一条淡一点的**预览**建议，整句结果回来覆盖它；
- 只移动光标不发请求；光标停在句号后面不动也不重送；
- 正文里只标 `quote` 那一小段：**删除画删除线，替换 / 补全画虚线**；
- **面板看不见就不画标记**：左侧栏收起、或者侧栏停在别的标签（文件列表 / 搜索 …）时，
  正文里不会留虚线 / 删除线；把面板切回来，标记自己回来，不用重新点条目；
- 一行一条：`×` 忽视、改后文本、`✓` 应用。点整行 = 在正文里高亮它说的是哪儿；
- `✓` 只替换那一小段，光标落在改后文本末尾，焦点留在正文；一步撤销（Ctrl/Cmd+Z）；
- `×` 只拿掉这一条和它的标记，不改正文、不发请求；
- 命令里缺密钥 / 缺模板 / 没开笔记会用 Notice 说一声，面板里不显示任何提示。

## 契约（系统固定，模板改不到）

模型必须回一个五字段 JSON：

```json
{"suggestions":[{"sentence":"要改的那一整句（逐字原文）","reason":"太含糊","quote":"句内要被替换的短片段","kind":"删除|替换|补全","rewrite":"改后的文本"}]}
```

本地按固定顺序过闸，任何一关不过就丢掉这一条：

1. `sentence` 在送检正文里逐字命中（不 trim、不兜底）；
2. `quote` 在这一句里逐字命中；
3. 条与条不重叠，按原文顺序；
4. `rewrite` 和原文不同；
5. 删除类 `rewrite` 必须为空串。

丢弃率本身就是模型能力的度量 —— 这里刻意不做容错纠偏。

## 记账：同样的文本、同样的标准，只花一次钱

每篇笔记、每种「扫描模式」都会记下**已经算过的句子**（模式 = 模板路径 + 模板正文 + 强度）。
换模板 / 改模板正文 / 换强度 → 旧记录作废、按新标准重扫；只换密钥不重扫。
记录按笔记路径存，所以**重命名笔记 = 新页 = 会重扫**。建议本身不持久化，重启客户端后面板是空的。

## 本机数据

- 设置、密钥、扫描记录：`<你的库>/.obsidian/plugins/obsidian-usage-norms/data.json`（**密钥明文**，不进 git、不上传）。
- 建议只在内存里，不写盘。
- 只有面板开着、且你在写的时候才会请求 `https://api.deepseek.com`。

## 目录

```
src/
  main.ts         插件入口：面板 / 编辑器事件 / 光标 / 设置联动 / 落盘
  view.ts         左侧边栏的视图（ItemView）
  settings.ts     设置页（模板文件夹 / 模板列表 / 强度 / reason / 密钥 / 记录）
  templates.ts    把「某个文件夹里的文件」读成模板
  store.ts        状态机：按句增量、预览、记账、作废在飞请求
  engine.ts       输出契约、解析闸门、DeepSeek 请求
  sentences.ts    切句（句号 / 换行 / 小数 / 日期 / Markdown 行首）
  decorations.ts  正文标记（删除线 / 虚线 / 高亮）
  visibility.ts   正文标记的开关：面板看得见才画（纯函数，单测覆盖）
examples/         三份能直接用的模板
```

## 排查（只在真机上出现的问题）

命令 `用语规范：导出调试日志（排查用）` 会把最近 400 条事件写成库根目录的
`用语规范调试.md`（只有事件名、文本长度、建议条数，**没有正文**）。真机上
复现问题后跑一次这个命令，把那个文件发过来就能定位。

iPad 上键盘弹起会让 Obsidian 收起 / 重排侧栏，**视图实例还在、DOM 却可能被换掉**。
0.1.5 之前踩的坑是「缓存了 body 节点」：行画进了已经脱离文档的孤儿节点，屏幕上
就是空的 —— 看起来就是「键盘一抬，左边就没了」。0.1.6 照 `obsidian-todo-panel`
的写法把这条彻底改掉（它的行不会因为侧栏重建而消失）：

- **不缓存任何 DOM**：每次 render 现查 `containerEl.children[1]`，body 没了就重建；
- **`onResize()` 直接重画**：Obsidian 官方的「视图尺寸变了」回调，比 window.resize 更早；
- **不缓存视图实例**：每次重画都 `getLeavesOfType` 现查活着的视图；
- **`onClose` 什么都不做**：不清建议、不挂起，只在真的没有叶子时停正文标记；
- 「面板在不在」= 工作区里还有没有这个叶子，不看 onOpen/onClose 记账；
- **400ms 自愈巡检**：面板开着时对一下「活容器里的行数 = 建议条数」，对不上就重画；
- 编辑事件照常送检；建议本来就不是持久化数据，所以靠内存里的 store 保留。

日志里会打 `view rebuild body` 和 `heal rows=a want=b`：真机再出现空栏时，
把日志导出来就能看出是容器被换掉、还是别的原因。

正文标记（删除线 / 底部虚线）另外做了两层兜底：CM6 视图先用 `editor.cm`，移动端
没有就从 DOM（`EditorView.findFromDOM`）找；CSS 用 `text-decoration-line/style`
长写法 + `!important`，防止主题把 span 的 `text-decoration` 清掉。日志里会打
`repaint marks=n/m`，能直接看出标记画没画上。

**类名必须带 `cm-` 前缀，而且和 `styles.css` 里的选择器一字不差。** 0.1.0–0.1.4
的「虚线和删除线一条都不显示」就是这里：`decorations.ts` 里写的是
`usage-norms-ins`，样式表里写的是 `.cm-usage-norms-ins`，标记画上去了、样式却
一条也没命中。`npm test` 里有一条用例专门比对这两边。

**面板看不见时一条标记都不画（0.1.7）。** 判据在 `src/visibility.ts`：叶子还在、
容器挂在文档里、`isShown()`、有实际宽高、所在分栏没收起 —— 任何一条不满足都当
「看不见」。这三种情况实测都会「有叶子但看不见」：左侧栏收起（sidedock
`collapsed`，动画结束才 `display:none`）、侧栏里切到别的标签（Obsidian 把非当前
叶子 `display:none`）、iPad 上抽屉收回。另外 `body` 上挂一个
`usage-norms-panel-visible` 类名兜底：**没有这个类，三条标记的样式全部作废**，
所以就算逻辑漏了一次，屏幕上也不会真的留下线。收起侧栏 / 切标签不一定有事件，
所以 300ms 巡检一次，只有状态真的变了才重画。

## 已知边界

- 面板跟随**当前活动笔记**；并排两篇时它只服务正在聚焦的那一篇。
- 侧栏建议不持久化；重启后不重扫（因为记账还在）。
- `reason` 只写不校验，模型可能写超 10 个字，不影响功能。
- 标记的开关看的是「面板看不看得见」，不是「在不在左边」：把面板拖到右侧栏、只要它
  露在外面，正文照样画标记。
- Obsidian 的移动端没有左侧边栏，面板在手机上会以普通视图出现。
